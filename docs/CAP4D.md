# 生成式数据增广的评估结论（CAP4D）

> 本文件只保留结论。CAP4D 的输入导出、渲染诊断等代码与测试已随该路线一起移除，
> 避免与后续工作混淆。

## 评估对象与方法

CAP4D 是一个预训练的多视角扩散模型（MMDM），以 4 张参考图 + FLAME 参数为条件
生成任意视角与表情的人像。我们用 RDF 跟踪自己的数据得到条件参数，生成了 212 帧，
并做了两组实验：

1. 把它作为补充训练数据（占每批约 7%），与不加增强的基线对比；
2. 让三份模型（基线、重训、含增强）分别去渲染这批生成图，观察对合成域的适应。

## 它确实提供了新覆盖

用拟合出的头姿与表情统计（`blend_weight` 前 100 维为表情、`[100:106]` 为头姿
rot6d）对比：

| 指标 | 真实数据（crh_1） | CAP4D 生成 |
|---|---|---|
| \|yaw\| 中位 | 0.7° | 16.7° |
| \|yaw\| P95 | 33.3° | 43.0° |
| 超过真实 P95 姿态的帧 | 5% | 19.3% |
| 表情幅值中位 | 8.2 | 13.8 |
| 超过真实 P95 表情的帧 | 5% | 90.6% |

**91.5%** 的生成帧在姿态或表情上超出真实分布的 P95。数据源本身是以正面为主的视频，
这批生成图补上的正是我们缺的大角度与大表情覆盖——"没有新信息"的判断不成立。

## 但监督质量不足

| 指标 | 真实数据 | CAP4D 生成 |
|---|---|---|
| 前景拉普拉斯能量（高频）| 8.73 | 6.76（−23%）|
| 前景平均梯度（轮廓）| 4.87 | 5.06（相当）|

轮廓保住了，纹理丢了。缺陷还包括普遍的颈部异常与单帧级的结构幻觉（如凭空出现手）。

下游代价：逐像素 RGB 监督等价于对高频施加平滑约束，验证指标下降 **0.86 dB**、
更早进入平台期、主观细节变糊；在生成集自身上重渲染时，最差帧由 8.9 dB 降到 5.4 dB
（低于 10 dB 的帧由 1 增至 6）——它把训练集中缺陷样本的缺陷也学了进去。

## 结构性限制不归我们控制

参考图上限 4 张（受训练设定约束）、不提供训练代码、无时序一致性、固定 512 分辨率、
身份一致性依赖随机参考组合。这些换数据集也改不了。

## 结论

**不作为训练数据来源。** 相关代码与测试已移除，仅保留本结论。

若将来要用它的覆盖度，前提是把监督改成"纹理无关"（只用轮廓 / alpha / 几何项），
那是一项独立研究，收益不确定；而覆盖度还有更便宜的来源（更大姿态与表情的真实采集、
几何侧的数据扩增），应优先考虑。

修复类方法（对真实图像做局部生成或修补）在身份与纹理保真上天然占优，与"补齐缺失
区域"的目标更匹配，作为独立路线另行评估。

目前正在验证的是 **SyncFix**（多视角联合精修：对降质渲染做跨视角一致的扩散修复，
支持用真实帧作参考）。它要求输入是同一场景的多视角渲染图，因此需要用我们自己的
模型渲染出多视角：

```bash
python scripts/make_syncfix_inputs.py --subject crh_1 --work-name run --frames 6
```

产出 `output/syncfix_<对象>/{input_pose,input_novel,gt,ref_image}` 与清单，
并打印可直接执行的 SyncFix 推理命令。评估口径：留出集上有 GT，看 PSNR/LPIPS
与高频能量是否改善、身份是否漂移；若官方权重（场景域训练）在人脸上崩坏，则停止。

## 可复用的判据

评估任何生成式数据源是否可用，先过三条必要条件，任一不满足就只能作为定性工具、
不能进入训练集：

1. **身份一致**（同一人的外观不随帧漂移）
2. **细节保真**（高频能量与真实数据同量级，例如差距 <5% 而非 23%）
3. **几何可控**（网格与姿态能被跟踪器稳定拟合，参数与图像内容一致）
