# 模型增强管线（规格）

> **内部记录**：本文含实验数据与数据集名称，仅用于内部评估。
> 对外展示前请清理具体数值与数据集名。

在**不改模型格式、不改数据**的前提下，用"找缺陷 → 外部精修 → 微调"提升已有模型的
渲染质量。本文是这条管线的规格：做什么、用什么参数、验收标准、实测结果与边界。

入口是 [`scripts/enhance_model.py`](../scripts/enhance_model.py)，四个阶段各自也可单独运行。

## 一、流程

| 阶段 | 做什么 | 产物 |
|---|---|---|
| 1 找缺陷 | 在视角 × 表情的候选池上渲染，按覆盖不足 / 孔洞 / 离面挑出问题视角 | `<缺陷目录>/{selected.json, views/, refs/, mass.npz}` |
| 2 外部精修 | 把 `views/` 交给精修器（当前用 SyncFix），参考图取 `refs/` | `refined/`（与视角同名） |
| 3 微调 | 用精修图做缺陷加权微调，按留出真值选检查点 | `<缺陷目录>/finetune/model.ply`、`models/<对象>/<名字>_refined/` |
| 4 评测 | 渲染测试 + 同视角缺陷对比 | 留出 PSNR、锐度比、结构缺口、云外溢 |

```bash
python scripts/enhance_model.py --subject crh_1 --work-name run \
    --syncfix-dir ~/Projects/SyncFix \
    --syncfix-model ~/Projects/SyncFix/model/official/ \
    --syncfix-env syncfix \
    --promote-name run_refined
```

## 二、默认参数（冻结）

**找缺陷**

| 参数 | 默认 | 说明 |
|---|---|---|
| 视角网格 | yaw ±40°、pitch ±20°，步长 10°，30° 以上加密到 5° | 覆盖常见通话头姿 |
| 表情池 | 12 个真实帧聚类中心 + 10 个主轴极值 | 前者覆盖本人习惯，后者补没做过的方向 |
| 预算 | 24 个组合 | 精修张数（实际受下面两条约束，通常选出 16–17 张） |
| 视角间隔 | `--min-angle-sep 6` | 避免同一角度占满名额 |
| 单帧上限 | `--per-base-max 3` | 同上 |

**微调**

| 参数 | 默认 | 说明 |
|---|---|---|
| 步数 | 600 | 300 步后损失基本平稳 |
| 参数范围 | 颜色 + 不透明度 + 尺度 | 尺度是补洞的必要项 |
| 批次 | 4 精修视角 + 4 真实帧 | 真实帧锚定，防止只拟合精修图风格 |
| 精修图体检 | 前景 IoU ≥ 0.5、色差 ≤ 60 | 不合格的视角跳过 |
| 选点帧 | 全数据集 `\|yaw\| ≥ 60` 分位的帧中随机 64 帧 | 不沿用预训练切片；这些帧不参与锚定 |
| 检查点判据 | `PSNR − 20·max(0, 训练前锐度 − 0.03 − 当前锐度)` | 锐度掉太多自动拒绝 |
| SSIM 项 | 0（关闭） | 个别构建上其 backward 会触发 CUDA 错误 |
| 精修批大小 | `--syncfix-batch 8` | 一次前向张数；失败会按批大小减半重试 |

**评测**：留出集 286 帧 PSNR + 锐度比；同一批缺陷视角的缺口 / 尖刺 / 云外溢。

## 二·补、激进模式（`--mode sweep`）

跳过缺陷评分与加权，直接问"哪些点数据看不够"，把它们当成必须覆盖的集合：

```bash
python scripts/enhance_model.py --subject crh_1 --work-name run \
    --mode sweep --budget 40 --sweep-coverage-max 4 \
    --syncfix-dir ~/Projects/SyncFix --syncfix-env syncfix \
    --promote-name run_sweep
```

| 项 | 缺陷模式（默认） | sweep 模式 |
|---|---|---|
| 目标 | 按缺陷质量加权（覆盖 + 孔洞 + 离面） | 观测次数 ≤ `--sweep-coverage-max` 的点，**权重一律为 1** |
| 约束 | 视角间隔 `--min-angle-sep`、单帧上限 `--per-base-max` | 都不加，优先铺开覆盖面 |
| 预算 | 16–24 | 建议 40+（目标点通常上千个，覆盖不完是正常的） |

适用场景：想验证"把能修的地方都修一遍"能否再涨，而不是挑最差的几处。
代价是精修张数上升（SyncFix 约 0.1 s/张）。张数到几十张时要控制每批大小：
`--syncfix-batch 8`（默认），显存不足会自动减半重试。

## 三、验收标准

| 指标 | 期望 |
|---|---|
| 留出集 mask 内 PSNR | ≥ 基线 +0.3 dB |
| 锐度比 | 不低于基线 −0.03 |
| 结构缺口 | 不恶化（可小幅下降） |
| 云外溢 | 不上升 |

四项同时满足才算通过；只涨 PSNR 而锐度大幅下降（>0.05）视为"用模糊换分"。

## 四、实测结果（crh_1）

### crh_1

| 版本 | 选点帧 | PSNR（286 帧，mask 内中位） | 锐度比 | 结构缺口 |
|---|---|---|---|---|
| `run`（基线） | — | 27.42 | 0.834 | 0.170 |
| `run_refined3` | 训练段随机 64 帧 | **28.16（+0.74）** | **0.87** | 0.165 |
| `run_refined4` | 大角度帧 | 28.17 | 0.87 | 0.165 |

### biden（另一个对象，验证可迁移性）

| 版本 | PSNR（mask 内中位） | 锐度比 | 结构缺口 |
|---|---|---|---|
| `train1`（基线） | 29.89 | 1.012 | 0.259 |
| 增强后 | **30.32（+0.43）** | 0.982 | 0.257 |

biden 的基线更高、锐度比大于 1（渲染比原图更锐），所以增强后锐度比回落 0.03
其实是**向真值靠近**，不是细节损失；这也说明"相对容差"守卫在基线与目标不同的对象上
同样适用。受影响的仍是外观（拟合精修图 +2.41 dB），结构缺口只降 0.8%。

### 激进模式（sweep，84 张）对照

| 版本 | 精修张数 | PSNR（64 帧，mask 内中位） | 锐度比 |
|---|---|---|---|
| `run`（基线） | — | 28.67 | 0.915 |
| `run_refined3` | 17 | **29.51（+0.84）** | 0.885 |
| `run_refined4` | 17 | 29.48（+0.81） | 0.888 |
| `run_sweep` | 84 | 29.41（+0.74） | 0.879 |

**结论：更多的精修图没有换来更好的结果。** 84 张（约 5 倍）反而略低于 17 张，
锐度比多掉 0.006。原因是 sweep 不区分"值不值得修"，把预算摊到本来就还行的区域，
同时把风格彼此不一致的目标图混进同一个微调里——在只能改颜色/不透明度/尺度的参数
空间里，这些目标互相拉扯，表现为轻微变糊。

这一轮的缺陷视角集合与默认模式不同（sweep 选的是另一批视角），所以缺口数值
（0.176 → 0.173）不能和 `run_refined3` 的 0.152 → 0.147 直接比。

- **+0.74 dB 是可复现的**：换一套选点帧，结果差 0.01 dB；
- 锐度比**上升**（0.834 → 0.87），不是拿细节换分；
- 结构缺口只降约 3%，与"修外观不修结构"的结论一致；
- **17 张已经接近这条路的实用上限**：扩到 84 张没有收益。

## 五、已知边界

- 只改善**外观**（色调、明暗、局部细节），不解决结构断裂、大角度空洞；
- 精修图在训练分布外（|yaw| > 40°）时收益递减，且可能引入增强器自身的偏差；
- 收益上限由精修器的输出质量决定，模型本身只在"已有参数"范围内调整；
- 因此它适合作为**交付前的最后一道外观修整**，不能替代数据覆盖或表示层改进。

## 六、常见问题

| 现象 | 处理 |
|---|---|
| SyncFix 报 `No module named imageio` | 用 `--syncfix-env syncfix` 或 `--syncfix-python <该环境解释器>` |
| SyncFix 显存不足（`CUDA out of memory`） | 调小 `--syncfix-batch`（默认 8；84 张一次过约需 11 GiB）。流程在失败时会自动按批大小减半重试两次 |
| 精修图数量少于视角数 | 精修器未跑完；`--skip-syncfix` 后可复用已有结果 |
| 换 `--promote-name` 后评测找不到模型 | 状态里记了目标名，会自动重跑微调；若被 `--force` 跳过则手动跑第 3 步 |
| 锐度比掉得多 | 手动降 `--lr-scaling`，或把 `--sharp-tolerance` 收紧到 0.02 |
