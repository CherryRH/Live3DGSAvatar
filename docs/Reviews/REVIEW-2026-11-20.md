## A. 五个 P0

### A1. "留出集"同时是验证集和选模型集 —— 目前没有真正未见过的测试集

`scripts/train.py:466` 用 `split="test"` 建 `val_src`；`ValidationHook` 在这个集合上
算 robust 分数、早停并保存 `model_best.ply`（`training/trainer.py:301-325`）；
`eval.sh:67-68` 又用同一个末尾 30% 范围评测。也就是说报告里的 holdout 数字是
**在测试集上 best-of-N 挑出来的**，而每个配置都在同一批帧上挑自己的最好值。

影响：绝对 PSNR 偏乐观；配置间比较混入选择偏差，消融的 0.1~0.3 dB 差距尤其不可信。

建议：训练段里再切 10% 作验证（或三路 train/val/test），测试集冻结且只在最后用；
`report.json` 明确写 `selection_split` 和 `test_split`。

**已解决（2026-11-20）**：按项目决定**不加第三份切分**，保持统一 30% 留出集。
改为把口径写清楚并量化代价：

1. `report.json` 新增 `params.evaluation`（`test_split` / `selection_split` /
   `selection_metric` / note）与 `params.provenance`（commit、模型 sha256、
   `metric_version`、mask 与孔洞阈值定义）；
2. 实测 bala `densify`：10 次验证的 robust 跨度 27.22–28.50，被选中的最好值就是
   最后一个 checkpoint（`model_004999.ply` 与 `model_005000.ply` 字节相同）——
   本行不存在 best-of-N 增益，但文档不再假装别的行也如此；
3. `docs/EVALUATION.md` 增加"评测口径与严谨性"：同一 30%、所有配置同帧比较、
   只有 `metric_version` 相同才能并排、消融必须同步数/同 LPIPS 启用点。

### A2. pose 驱动的头转 mesh 不闭环：`turn(idx, 0)` 不等于训练数据里的 mesh

`PoseDriver` 用 RDF 的 `x` 重新跑一遍 FLAME，再用一次 Kabsch 把结果贴到烘焙 mesh 上
（`tracking/pose_drive.py:101-119`）。实测在 **dyaw=0**（本应是恒等变换）时：

| 数据集 | 帧 | 与烘焙 mesh 的偏差 mean | p99 |
|---|---|---|---|
| bala | 2236（修复图基帧） | 2.94 mm | 18.7 mm |
| bala | 3000 | 3.04 mm | 21.2 mm |
| guided_capture_01 | 2000 | 3.02 mm | 21.3 mm |

根因方向（需开发者确认）：烘焙路径是 `mesh = teeth.build(rdf.verts)`，即直接用跟踪器
自己的顶点；而 `PoseDriver._build()` 把 `global @ neck` 合成后塞进 FLAME 的 **neck**
关节、`root` 留单位阵（`pose_drive.py:106-108`），与 `checkpoint_loader.py:154-176`
记录的"全局旋转挪到 neck + 平移补偿 `t'=R·neck_j−neck_j+t`"约定不一致；同时
`weight[126:129]`（平移）在转头后从未更新（`pose_drive.py:139-141`）。同一帧的闭环
误差已经是 p99 1–2 cm、最大 3 cm 的量级，转 40° 后还会放大。
（guided_capture_01 的烘焙 mesh 与 `rdf.verts` 完全一致（0.00 mm），闭环误差仍一样，
说明这不是 bala"新旧跟踪混用"造成的特例。）

影响：22 张修复图、每 4 步的新视角监督、robust 评测（它决定 checkpoint）、GUI 头转
全部建立在这套 mesh 上。主表 PSNR 不受影响（渲染真实帧），但模型选择受影响。

建议：不要"重算 FLAME 再配准"，直接对已烘焙 mesh 做绕颈关节的刚体旋转，或严格复用
烘焙约定（root/neck 分开 + 平移补偿）；先加一个黄金测试
`turn(idx, 0) ≈ mesh[idx]`（阈值 2 mm），过了再谈大角度。

**已解决（2026-11-20）**：按建议改成**纯蒙皮旋转**，不再重算 FLAME：

- `v' = v + w_h·(D·(v−J) + J − v)`，`w_h` 取 FLAME 的 `1 − root` 权重
  （下颌/眼球随颈转，牙齿权重已补），`J` 用 RDF 的 identity 算出的颈关节
  （缺 RDF 时用过渡带质心兜底，对 yaw 而言 J 沿旋转轴的分量不影响结果）；
- `turn(idx, 0)` 与烘焙 mesh **逐位相同**（误差 0.0 m，驱动参数也不变）；
  60° 时头骨平均位移 91 mm、颈根 11 mm；`weight[126:129]` 不再需要更新
  （顶点本身携带位姿）；
- 黄金测试落在 `tests/unit/test_pose_drive.py`（闭环、头动/颈根不动、缓存、牙齿权重）；
- 顺带把"有/无 RDF 就走不同语义"的开关去掉：只要烘焙 mesh 是 FLAME 拓扑，
  修复图/评测/前端都走头转（不可用时才退回相机绕转）。

### A4. base↔densify 是容量混淆比较，而且报告记录了错误的模型结构

bala `base` = tex 256 / 60,353 高斯；`densify` = tex 512 / 74,503 高斯。所谓
"+0.2 dB、SSIM/LPIPS 更好"因此不能归因于 alpha 项、SSIM/LPIPS 损失或修复图。
更糟的是 `report.json` 的 `params.model_structure` 是从 **CLI 默认值**写的
（`scripts/render_test.py:771-777`），所有 bala 报告都写 `tex_size: 256`，而实际
PLY 是 512 —— 报告自己把混淆项抹掉了。

同一区域还有一个哑弹：`--no-lpips` 只影响一条 warning（`render_test.py:656`），
LPIPS 照样计算；`densify_train.sh:111` 每轮 eval 都传 `--no-lpips`，报告里的
`params.render.lpips` 于是写着 `false` 却仍有 LPIPS 数值。

建议：报告写**实际加载**的 `avatar.config` 与每模型 `num_gaussian`；补一个同容量
基线（tex 512、同步数）；修掉或删掉 `--no-lpips`。

### A5. 新加的 alpha 两项在标准指标上是负收益，唯一正面证据不在产物里

刚跑完的消融（bala，1198 帧，3000 步、batch 8、tex 512，命令只差 alpha 相关开关）：

| 版本 | mask PSNR | SSIM | LPIPS↓ | 锐度比 |
|---|---:|---:|---:|---:|
| ctrl（alpha 0.2 + sat 0.03，默认） | 29.55 | 0.8713 | 0.0699 | 0.801 |
| nosat（关饱和项） | 29.27 | 0.8721 | **0.0597** | 0.835 |
| noalpha（关 alpha L1 + 饱和项） | **29.66** | **0.8740** | 0.0632 | 0.832 |

关掉这两项后 SSIM、LPIPS、锐度一致变好，PSNR 差异在噪声内。唯一支持它们是
"半透明暗像素 6.53% → 1.47%"这个一次性诊断，它不在 `report.json` 里，无法复核。

建议：把 haze/alpha 覆盖度做成报告的正式字段，用同一批帧给出
"PSNR/SSIM/LPIPS/锐度 vs haze"的两轴表；在此之前不要把它写成"默认更好"。

## B. 训练/选择回路的 6 处不一致（会直接改数字）

1. **硬表面验证和训练不是同一个前向**：训练有 `scaling.clamp(max)` + 前表面剔除
   （`train.py:866-872`），验证直接 `render_frame`（`train.py:1009-1013`，无 clamp、
   `frontface=False`）。stage1 的早停/`model_best` 因此选的可能不是训练时那个模型。
2. **新视角监督绕过 `blend_start`**：训练主路径在 warm-up 传 `weight=None`
   （`trainer.py:202`），pose 分支却总是传 `turned.weight`（`train.py:921-925`）。
   默认 `blend_start=3000` + 每 4 步一次新视角，等于形变基被提前训练了约 750 次——
   "前 3000 步只学静态外观"的消融不成立。
3. **报告的最佳分数和落盘的 `model_best.ply` 可能不是同一个 checkpoint**：
   `on_improve` 只在超过 `min_delta` 时存盘，`on_end` 却把 `report.best_metric`
   改成 history 的最大值（`trainer.py:317-325` + `schedule.py:78-85`）。
4. **早停时 `report.iterations` 多 1**：`trainer.py:182-190` 在 break 后 +1；
   现有测试 `tests/unit/test_training.py:388-395` 把这个 off-by-one 固化了。
5. **`--nv-hole-weight > 0` + `--repair-dir` 会崩**：`MixedHardSource` 没有
   `iter_batches`（`train.py:405-454`），而 `sample_face_stats` 会调用它
   （`train.py:1197`）。默认 hole_weight=0，所以是个潜伏的死参数。
6. **`--early-metric` 可以和 stage 不匹配而静默失效**：`train.py:1151-1153` 不做校验，
   `ValidationHook` 在 metric 不存在时永远不 update（`trainer.py:307-313`），
   最后一轮写出 `best_metric=-inf`，跑满预算却没有 best 模型。

建议：把"训练用的前向/权重开关"收成一个函数，训练与验证共用；`report` 只记录
真正落盘的那个 checkpoint；启动时校验 metric 与 stage/config 的组合。

## C. 数据与评测口径（P1）

- **同一张表里语义不一致**：只有 `bala`、`biden`、`guided_capture_01` 有
  `rdf_tracking.npz`；`crh_1`/`crh_new` 和 6 个 INSTA 数据集没有。于是 showcase /
  GUI 在这些数据集上仍走"相机绕转"，另外三个走"头转"——图注里目前没写这件事。
- **SSIM/LPIPS 不是真正的 mask 指标**：SSIM 在全图上滤波、只在 mask 内取平均；
  LPIPS 完全不管 mask；锐度有三套定义（`protocol.py:128-133`、`:159`、
  `defects.py:213-218`，其中两处多乘了 255）。背景色会自动切换，SSIM/锐度会跟着变
  （实测同一内容黑白底切换：masked SSIM 0.9552、锐度差 16%）。
- **报告缺关键溯源**：没有 git commit/dirty、模型文件 hash、指标实现版本、LPIPS
  权重版本、mask 定义、孔洞阈值。`params.config` 还是**评测时**的 `configs/`，
  不是训练快照（同一 eval 代码下 base 记录 `alpha_weight: None`、densify 记录 0.2）。
- **FPS 不可复现**：单次、1 帧 warmup、无重复、无方差、无 GPU 独占/频率记录；
  同一模型同一批帧在两次报告里能差 100+ FPS。
- **消融设计**：`S1_HOLE`/`S1_SPILL` 只进 stage1 命令（`densify_train.sh:80-84,137`），
  stage2 三组命令逐字节相同。因此这组消融只能说明"初始化阶段的表面项没有可测影响"
  （29.62 / 29.55 / 29.40，差异 ≈ 噪声且无同配置重复），**不能**支持
  "spill 抑制侧面漂浮"的结论。要么在 stage2 也做，要么把结论改窄。
- **robust 指标**：孔洞阈值 0.5 硬编码在三处、不进报告；"面外溢出"统计的是 FLAME
  轮廓外的实心像素（含头发/肩），和训练里同名 loss（alpha∈0.05–0.6）不是一回事。
  建议改名（`opaque-outside-flame`）并记录阈值与视角语义。
