## 二、本周新增的 5 个 P0

### 2.1 核心贡献没有对照消融：现在无法证明"SyncFix 监督"有用

六次训练里，`base → avatar` 同时改了：修复图、LPIPS 0.01、SSIM 0.05→0.1、
初始化路径（`init_uv`+`merge_layers` vs `train.py` 内建）、步数/早停
（tex 512 只是给 split 留容量，不加密时无实质影响）。`avatar → rgb` 又改了
初始化、SSIM 0.2、随机背景、无 alpha/spill。**只有修复图开/关这一项从未单独
跑过**。

后果：biden 上 `rgb` 的 mask PSNR 反而最高（30.31 vs avatar 29.87，+0.44 dB），
所以"avatar 留出集不输"目前只对 `base` 成立，对 `rgb` 是**混合**的（SSIM/LPIPS
更好、PSNR 更低）。审稿人一定会问的正是"去掉修复图会掉多少"。
另外 avatar 是唯一把 LPIPS 放进损失的模型，它的 LPIPS 优势有一部分是
"直接优化被报指标"，对比表里应注明（或给 no-LPIPS 版本）。

最小补法（一天内可跑完，bala 一对象即可）：`avatar` 同配置 + `--repair-per-batch 0`，
固定 7000 步、同 SSIM/LPIPS；比较 mask PSNR/SSIM/LPIPS/haze 与大角度分桶。
这一条不补，"syncfix 参与监督"只能算工程选择，不能算方法贡献。

### 2.2 "大角度远强于其他模型"超出产物能支撑的范围

我把六份 `report.json` 的逐帧指标按头姿 yaw 分桶（同一帧、同一指标，跨模型可比）：

| 数据集 / 桶 | n | base | rgb | avatar |
|---|---:|---:|---:|---:|
| bala \|yaw\|<10° | 1101 | 29.46 / .871 / .069 | 29.78 / .887 / .056 | **30.04 / .889 / .054** |
| bala 10–30° | 20 | 29.54 / .851 / .081 | 29.20 / .861 / .072 | **30.27 / .865 / .067** |
| bala ≥30° | 77 | 32.71 / .893 / .082 | 32.56 / .904 / .074 | **32.86 / .908 / .063** |
| biden <10° | 824 | 29.75 / .945 / .038 | **30.31 / .942 / .045** | 29.87 / .944 / **.036** |
| biden ≥10° | 4 | 27.80 / .917 / .048 | 27.26 / .911 / .060 | 27.44 / .911 / .046 |

（mask PSNR / mask SSIM / LPIPS，均为中位；`biden` 留出集**没有 ≥20° 的帧**。）

同时看 ±45° 无 GT 代理指标：avatar 在 `haze/outside` 上明显最好（bala +45°：
haze 0.9% vs base 2.6% vs rgb 20.5%），但 **`coverage/hole` 并不比 base 好**
（0.872/0.128 vs 0.887/0.113）；rgb 的 coverage 最高（0.941）恰恰因为它更"蓬"
（outside 0.233、area 113k vs avatar 93k）。也就是说：

- **能支撑的说法**：avatar 的轮廓更干净（haze/outside 低一个量级），bala 大角度
  分桶里三项指标都最优，但相对 base 的领先只有 +0.15 dB / +0.015 SSIM 量级；
- **不能支撑的说法**："几何完整性远强于其他模型"（coverage/hole 反而略低），
  以及"biden 大角度也更好"（biden 没有大角度留出帧）。

另外，修复图在 biden 做到 ±80°、bala 做到 ±90°，而 **GT 最大只到 12.6°/50.4°**；
`output/repair/bala/views/yaw+90_...png` 是噪声、`repairs/yaw+90_...png` 是一张
干净的侧脸——这已经不是"修复"，是**生成**。方法上没问题，但必须写成
"self-supervision / plausible completion"，不能写成"修复了大角度观测"。

建议：① 报告加"按 |yaw| 分桶的 GT 指标"（用现有 `per_frame` + 数据集 yaw 就能算，
不需要重跑）；② 报告大角度表固定给 ±60/±75，并把 `id_cos`（`large_angle_metrics.py`
已有，正脸 1.0 → +75° 0.47）纳入；③ 措辞收窄到"轮廓更干净、大角度 GT 分桶不弱"。

### 2.3 选模型仍发生在报告集上，而且收益最大的是 avatar

`best_iteration` 普遍在中段：bala/avatar 5499/7500、biden/avatar 4499/6500、
biden/rgb 2499/4500。用各自 `eval_history` 的"选中点 vs 末点"估一下选择收益
（同一批 240 帧验证集）：

| 模型 | best PSNR | last PSNR | ΔPSNR |
|---|---:|---:|---:|
| bala avatar | 30.23 | 29.43 | **+0.80** |
| biden avatar | 29.92 | 29.19 | **+0.73** |
| biden rgb | 30.33 | 29.61 | +0.72 |
| biden base | 29.78 | 29.35 | +0.43 |
| bala base | 29.60 | 29.38 | +0.23 |
| bala rgb | 29.83 | 29.52 | +0.31 |

`EVALUATION.md` 已经诚实写了"best-of-N on test"，但**受益最大的正好是 avatar**，
所以现在的"avatar 更强"里混着 0.7~0.8 dB 的选择偏差。最小修法：报告同时给
"末个 checkpoint（固定预算）"一列；或把验证集从训练段切（10%），报告集冻结。
另外报告里的 `selection_metric` 必须改成实际的 `score` 公式。

### 2.4 修复图不可复现，也不绑定 base 模型

`datasets/biden/repair/manifest.json` 声称 35 个角度，实际 `repairs/` 只有 28 张
（+70/+75/+80/+85/+90、-85/-90 被 cap 丢掉），manifest 里**没有 `kept`/`dropped`/
丢弃原因**，`source` 还写着"BiRefNet alpha"（默认已改 key）。更关键的是：

- manifest 没有 base `model.ply` 的 hash/mtime，`train_avatar.sh` 只检查目录非空；
  重训 base 后，avatar 会**静默**继续用旧修复图；
- SyncFix 的 `--seed` 解析了但没用（`SyncFix/inference.py:24`），采样是
  `randn_like`；`n_per_pass=4` 的联合 forward 让某角度的 label 取决于同批邻居，
  而分组没有记录；
- `_g_*` 分组目录和 `refs/` 不清空，重跑会混入上一轮的角度/参考；
- `refs_auto` 把切分硬编码成 `1-0.3`，`test_ratio` 调大就会把留出帧喂给 SyncFix。

这四条合起来：**最终 avatar 的监督标签无法从仓库和当前产物复现**。修法：
manifest 写 base hash + SyncFix commit/权重 hash + seed + 实际 kept/dropped +
refs 帧号；`train_avatar.sh` 校验 hash（不匹配就拒绝）；SyncFix 传 seed；每次
清空 `_g_*`/`refs/`；refs 用配置里的 `test_ratio` 并断言 `< train_end`。

### 2.5 训练报告字段本身就是错的

- `models/bala/avatar/report.json` 的 `best_psnr` = **121.06**，实际是
  `report.best_metric`（`score = PSNR+50·SSIM+50·(1−LPIPS)`，`train.py:1516`）；
  任何按"PSNR"读取/画图的脚本都会错。
- `best_saved` 在 `TrainReport` 里有（`trainer.py:79-84`），但**没序列化**。
- 六份评测报告全部 `git_dirty: true`（在 `c218892` 上产出，HEAD 已到 `5bb64d6`），
  所以 commit 不能唯一确定代码。
- `provenance.mask` 写 `alpha>127`，评测实际用 `alpha>250`（`render_test.py:788`）。
